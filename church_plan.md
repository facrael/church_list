# План разработки приложения "Религиозный маркетплейс"

## 📋 Описание проекта

Мобильное приложение для Android и iOS — единый маркетплейс религиозных услуг, где верующие могут находить храмы, бронировать услуги, оплачивать их онлайн и получать религиозный контент.

---

## 🎯 Видение и цели

### Основная идея
Создать цифровую платформу "всё в одном" для:
- 🕌 Поиска храмов/мечетей/синагог рядом
- 📝 Бронирования религиозных услуг
- 💳 Онлайн-оплаты услуг и пожертвований
- 📖 Получения религиозного контента
- 👥 Взаимодействия с общиной

### Цели для разных сторон

**Для пользователей:**
- Упростить доступ к религиозным услугам
- Экономия времени (без звонков и личных визитов)
- Единый цифровой сервис

**Для храмов/организаций:**
- Дополнительный канал привлечения прихожан
- Упрощение учета услуг и пожертвований
- Повышение прозрачности и доверия

**Коммерческая цель:**
- Комиссия с платежей за услуги (5-10%)
- Комиссия с пожертвований (3-5%)
- Платные функции для храмов (B2B подписка)
- Премиум-подписка для пользователей (опционально)

## 💡 Конкурентное преимущество

### Анализ конкурентов
**Изучены**: Pray.com, YouVersion Bible App, Eparhia, Orthodox Calendar

**Их минусы:**
- ❌ Нет бронирования услуг
- ❌ Нет оплаты религиозных услуг
- ❌ Нет единого сервиса «карта → заказ → оплата»
- ❌ Слабая коммерческая модель

### Наше УТП
> **"Религиозный маркетплейс услуг + карта + оплата + контент"**

Единственное приложение на рынке РФ с полным циклом от поиска до оплаты религиозных услуг.

### Основные таблицы

#### Churches (Храмы)
```sql
- id (UUID, PK)
- name (String)
- religion (ENUM: orthodox, islam, judaism)
- denomination (String)
- description (Text)
- latitude (Double)
- longitude (Double)
- address (String)

- phone (String)
- email (String)
- website (String)
- photos (Array<String>)
- working_hours (JSONB)
- rating (Decimal)
- verified (Boolean)
- created_at (Timestamp)
- updated_at (Timestamp)
```

#### Services (Услуги)
```sql
- id (UUID, PK)
- church_id (UUID, FK)
- name (String)
- description (Text)
- category (String)
- price (Decimal)
- duration (Integer) // минуты
- is_available (Boolean)
- requires_booking (Boolean)

- created_at (Timestamp)
```

```sql
- id (UUID, PK)
- user_id (UUID, FK)
- service_id (UUID, FK)

- booking_date (Timestamp)
- status (ENUM: pending, confirmed, completed, cancelled)
- payment_status (ENUM: pending, paid, refunded)
- payment_amount (Decimal)
- commission_amount (Decimal)
- notes (Text)
- contact_phone (String)
- created_at (Timestamp)
- updated_at (Timestamp)
```

#### Events (Мероприятия)
```sql
- id (UUID, PK)
- church_id (UUID, FK)
- title (String)
- description (Text)
- event_type (ENUM: service, holiday, special, pilgrimage)
- start_time (Timestamp)
- end_time (Timestamp)
- is_recurring (Boolean)
- recurrence_rule (String)
- created_at (Timestamp)
```

#### Users (Пользователи)
```sql
- id (UUID, PK)
- phone (String, unique)
- email (String)
- name (String)
- religion (ENUM)
- avatar (String)
- role (ENUM: user, church_admin, admin)

- created_at (Timestamp)
```

#### Payments (Платежи)
```sql
- id (UUID, PK)
- user_id (UUID, FK)
- booking_id (UUID, FK, nullable)
- church_id (UUID, FK)
- amount (Decimal)
- commission (Decimal)
- type (ENUM: service, donation)
- status (ENUM: pending, success, failed, refunded)
- payment_method (String)
- payment_provider (String)

```

#### Content (Контент)
```sql
- id (UUID, PK)
- type (ENUM: prayer, audio, podcast, article, video)
- title (String)
- content (Text)
- audio_url (String)
- video_url (String)
- religion (ENUM)
- category (String)
- views (Integer)
- created_at (Timestamp)
```

#### Communities (Общины)
```sql
- id (UUID, PK)
- name (String)
- description (Text)
- church_id (UUID, FK, nullable)
- admin_id (UUID, FK)

- member_count (Integer)
```

## 💰 Бизнес-модель и монетизация

### Источники дохода

1. **Комиссия за услуги** (5-10%)
   - При каждой оплате религиозной услуги
   - Прогноз: 100-300 заказов/день × 1000₽ × 7% = 7,000-21,000₽/день

2. **Комиссия за пожертвования** (3-5%)
   - Более низкая ставка для благотворительности
   - Прогноз: 50-150 пожертвований/день × 500₽ × 4% = 1,000-3,000₽/день

3. **B2B подписка для храмов** (2,990-9,990₽/мес)
   - Базовая: 2,990₽/мес (до 50 заказов)
   - Стандарт: 4,990₽/мес (до 200 заказов)
   - Премиум: 9,990₽/мес (безлимит + приоритет в поиске)
   - Прогноз: 100 храмов × 4,990₽ = 499,000₽/мес

4. **Премиум-подписка для пользователей** (199₽/мес)
   - Без рекламы
   - Эксклюзивный контент
   - Скидки на услуги (5-10%)
   - Прогноз: 1,000 пользователей × 199₽ = 199,000₽/мес

5. **Реклама** (опционально)
   - Нативная реклама религиозных товаров
   - Промо-посты от храмов

### Прогноз выручки (через 12 месяцев)
- Комиссии: ~300,000-700,000₽/мес
- B2B подписки: ~500,000₽/мес
- Премиум: ~200,000₽/мес
- **Итого**: 1-1.5 млн₽/мес

## 📡 Спецификация API (REST Endpoints)

### API Documentation
- **Swagger UI**: `https://api.yourapp.com/docs`
- **Format**: OpenAPI 3.0
- **Base URL**: `https://api.yourapp.com/api/v1`
- **Auth**: Bearer JWT Token in Header

### Общие правила

#### Формат дат
- **Стандарт**: ISO 8601 (`YYYY-MM-DDTHH:mm:ssZ`)
- **Примеры**: 
  - `2026-01-26T15:30:00Z`
  - `2026-12-31T23:59:59+03:00`

#### Стандарт ответов API

**Success Response:**
```json
{
  "success": true,
  "data": { ... },
  "meta": {
    "timestamp": "2026-01-26T15:30:00Z",
    "version": "1.0"
  }
}
```

**Error Response:**
```json
{
  "success": false,
  "error": {
    "code": "CHURCH_NOT_FOUND",
    "message": "Храм с указанным ID не найден",
    "details": {},
    "timestamp": "2026-01-26T15:30:00Z"
  }
}
```

#### Коды ошибок
```
AUTH_001: Invalid credentials
AUTH_002: Token expired
AUTH_003: Invalid token

CHURCH_001: Church not found
CHURCH_002: Church not verified

SERVICE_001: Service not found
SERVICE_002: Service unavailable

BOOKING_001: Invalid booking date
BOOKING_002: Booking slot not available
BOOKING_003: Booking limit exceeded

PAYMENT_001: Payment failed
PAYMENT_002: Payment declined
PAYMENT_003: Invalid payment method
```
